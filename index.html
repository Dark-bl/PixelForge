CAPÍTULO 01

Introducción a la programación

Programar es escribir instrucciones precisas para que una computadora realice una tarea. Un programa recibe datos, procesa esos datos mediante reglas y produce un resultado. No necesitas memorizar un lenguaje completo: primero aprende a dividir un problema en pasos pequeños.

Algoritmo

Secuencia finita y ordenada de pasos para resolver un problema. Ejemplo: preparar una bebida, desde llenar el vaso hasta servir.

Lenguaje

Conjunto de reglas y palabras que permite expresar instrucciones: Python, JavaScript, C#, GDScript o Dart.

Programa

Implementación de un algoritmo en un lenguaje que el entorno puede ejecutar.

Los bloques fundamentales

  • Variables: nombres asociados a valores, por ejemplo puntos = 0.
  • Tipos: números, texto, valores booleanos y colecciones.
  • Condiciones: permiten elegir una ruta: si ocurre algo, entonces...
  • Ciclos: repiten instrucciones mientras se cumpla una condición o por cada elemento.
  • Funciones: agrupan instrucciones con un nombre y pueden recibir datos y devolver resultados.
  • Errores: sintaxis (reglas mal escritas), ejecución (falla al correr) y lógica (el programa corre, pero responde mal).

Ejemplo cotidiano convertido en algoritmo

  1. Leer el total de una compra.
  2. Si el total supera 500, calcular un descuento del 10 %.
  3. Mostrar el importe final.
total = 650
if total > 500:
    total = total * 0.90
print("Total a pagar:", total)

Prueba mental: con un total de 400 no se aplica descuento; con 650 el resultado es 585. Practica describiendo primero la solución con palabras y después tradúcela a código.

CAPÍTULO 02

Preparación del entorno de trabajo

Un entorno de trabajo reúne el equipo, el sistema operativo, el editor, los SDK o motores y las herramientas para probar el proyecto. Una computadora reciente de uso general suele bastar para comenzar con páginas web y ejercicios; el desarrollo 3D y los emuladores móviles pueden exigir más memoria y una GPU compatible.

Ruta de instalación sugerida en Windows

  1. Actualiza Windows y comprueba que tengas espacio disponible.
  2. Instala Visual Studio Code.
  3. En VS Code instala extensiones solo desde el Marketplace oficial; para HTML/CSS/JS puedes empezar sin extensiones adicionales.
  4. Descarga Godot 4 para el primer videojuego. La versión estándar es suficiente para GDScript.
  5. Para Flutter, sigue la guía oficial de instalación de Flutter, instala el SDK y Android Studio si vas a usar el emulador Android.
  6. Abre una terminal y ejecuta flutter doctor; corrige los elementos que el diagnóstico marque como pendientes.
  7. Crea una carpeta por proyecto y conserva nombres claros: assets, scenes, scripts o lib, según la herramienta.
Consejo: instala una herramienta a la vez y abre un proyecto de prueba antes de agregar otras. Así podrás identificar qué instalación causó un problema.

Tutorial: juego 2D de recolección en Godot 4

Resultado: controlarás un personaje visto desde arriba, recogerás monedas, sumarás puntos y terminarás al recogerlas todas. El tutorial usa formas simples para que no dependas de imágenes externas. Requiere Godot 4.x; consulta la documentación estable si tu versión cambia.

  1. Abre Godot, selecciona New Project, escribe Recolector2D y crea el proyecto con renderizador recomendado para tu equipo.
  2. En Project > Project Settings > Display > Window, configura una ventana de 960 × 540. En Input Map agrega las acciones mover_izquierda, mover_derecha, mover_arriba, mover_abajo y asigna A/D/W/S o flechas.
  3. Crea una escena Player.tscn con raíz CharacterBody2D llamada Player. Añade CollisionShape2D con forma CircleShape2D y un Polygon2D o Sprite2D como apariencia. Guarda en scenes/.
  4. Adjunta el script scripts/player.gd a Player:
extends CharacterBody2D

@export var speed: float = 260.0

func _physics_process(_delta: float) -> void:
    var direction := Input.get_vector(
        "mover_izquierda", "mover_derecha",
        "mover_arriba", "mover_abajo"
    )
    velocity = direction * speed
    move_and_slide()
    var bounds := get_viewport_rect().size
    position = position.clamp(Vector2(16, 16), bounds - Vector2(16, 16))
  1. Crea Coin.tscn con raíz Area2D llamada Coin, añade CollisionShape2D con CircleShape2D y un Polygon2D de color amarillo. Adjunta:
extends Area2D
signal collected

func _ready() -> void:
    body_entered.connect(_on_body_entered)

func _on_body_entered(body: Node2D) -> void:
    if body is CharacterBody2D:
        collected.emit()
        queue_free()
  1. Crea Main.tscn con raíz Node2D llamada Main. Añade una instancia de Player como hijo directo y crea un nodo Node2D llamado Coins; coloca dentro varias instancias de Coin. Distribúyelas dentro del área visible.
  2. Añade un CanvasLayer llamado HUD y, dentro, un VBoxContainer con cuatro nodos: ScoreLabel (Label), StateLabel (Label), StartButton (Button, texto “Iniciar”) y RestartButton (Button, texto “Volver a jugar”). El árbol debe quedar así: Main/Player, Main/Coins/Coin... y Main/HUD/VBoxContainer/(ScoreLabel, StateLabel, StartButton, RestartButton).
  3. Adjunta a Main el script siguiente. Los botones se conectan desde código para que no tengas que crear conexiones manuales:
extends Node2D

@onready var score_label: Label = $HUD/VBoxContainer/ScoreLabel
@onready var state_label: Label = $HUD/VBoxContainer/StateLabel
@onready var start_button: Button = $HUD/VBoxContainer/StartButton
@onready var restart_button: Button = $HUD/VBoxContainer/RestartButton
@onready var player: CharacterBody2D = $Player
@onready var coins_root: Node2D = $Coins

var score: int = 0
var total_coins: int = 0
var started: bool = false

func _ready() -> void:
    var coins := coins_root.get_children()
    total_coins = coins.size()
    player.set_physics_process(false)
    for coin in coins:
        coin.collected.connect(_on_coin_collected)
        coin.hide()
    start_button.pressed.connect(_start_game)
    restart_button.pressed.connect(_restart_game)
    restart_button.hide()
    state_label.text = "Presiona Iniciar para comenzar"
    _update_score()

func _start_game() -> void:
    started = true
    player.position = get_viewport_rect().size / 2.0
    player.set_physics_process(true)
    for coin in coins_root.get_children():
        coin.show()
    start_button.hide()
    state_label.text = "¡Recoge todas las monedas!"
    if total_coins == 0:
        _finish_game()

func _on_coin_collected() -> void:
    if not started:
        return
    score += 1
    _update_score()
    if score >= total_coins:
        _finish_game()

func _finish_game() -> void:
    started = false
    player.set_physics_process(false)
    state_label.text = "¡Nivel completado!"
    restart_button.show()

func _restart_game() -> void:
    get_tree().reload_current_scene()

func _update_score() -> void:
    score_label.text = "Monedas: %d / %d" % [score, total_coins]
Importante para que funcione: las monedas deben ser hijas del nodo Coins y llamarse/instanciarse desde la escena Coin. La ruta de los nodos HUD debe coincidir exactamente con el árbol indicado. Cada Coin emite la señal collected y se elimina con queue_free().
  1. Define Main.tscn como escena principal desde Project > Project Settings > Application > Run o pulsa el botón para establecer la escena actual.
  2. Ejecuta con F6 para probar la escena o F5 para el proyecto. Comprueba movimiento, límites, colisiones y puntuación.
  3. Para una pantalla de inicio y final, crea un Control con botones Iniciar/Reintentar y un panel de resultado. Ocúltalo al empezar; al terminar, muéstralo. Conecta las señales pressed de los botones a funciones que reinicien la escena o cambien el estado del juego.

Pruebas mínimas

  • El personaje se mueve en cuatro direcciones y no se desplaza cuando no pulsas nada.
  • Una moneda desaparece una sola vez y el contador aumenta exactamente uno.
  • Al recoger todas las monedas aparece el mensaje de nivel completado.
  • La escena se ejecuta con el tamaño de ventana definido.

Este ejemplo enseña nodos, escenas, físicas, señales y HUD. Para una versión con enemigos, temporizador y reinicio completo, sigue el tutorial oficial Tu primer juego 2D.

CAPÍTULO 04

Desarrollo de aplicaciones móviles

Una aplicación móvil presenta información y permite realizar acciones con controles táctiles. Flutter usa Dart para crear interfaces desde una base de código; Android Studio ofrece emulador y herramientas Android. MIT App Inventor permite aprender con bloques visuales.

Herramientas

  • Flutter/Dart: aplicaciones multiplataforma con widgets.
  • Android Studio: SDK, emuladores y herramientas de compilación Android.
  • VS Code: editor ligero con extensiones oficiales de Flutter y Dart.
  • MIT App Inventor: prototipos educativos mediante programación por bloques.

Tutorial: lista de tareas en Flutter

  1. Instala Flutter siguiendo la guía oficial para tu sistema.
  2. Instala Android Studio y un Android SDK compatible si probarás en emulador.
  3. En terminal ejecuta flutter doctor y resuelve los avisos antes de continuar.
  4. Ejecuta flutter create lista_tareas y entra en la carpeta con cd lista_tareas.
  5. Abre lib/main.dart y reemplaza su contenido por este ejemplo.
import 'package:flutter/material.dart';

void main() => runApp(const TodoApp());

class Task {
  Task(this.title);
  final String title;
  bool done = false;
}

class TodoApp extends StatelessWidget {
  const TodoApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      title: 'Mi lista de tareas',
      theme: ThemeData(colorSchemeSeed: Colors.deepPurple,
          useMaterial3: true),
      home: const TodoPage(),
    );
  }
}

class TodoPage extends StatefulWidget {
  const TodoPage({super.key});

  @override
  State<TodoPage> createState() => _TodoPageState();
}

class _TodoPageState extends State<TodoPage> {
  final List<Task> tasks = [];
  final TextEditingController controller = TextEditingController();

  void addTask() {
    final title = controller.text.trim();
    if (title.isEmpty) return;
    setState(() {
      tasks.add(Task(title));
      controller.clear();
    });
  }

  void toggleTask(int index, bool? value) {
    setState(() => tasks[index].done = value ?? false);
  }

  void deleteTask(int index) {
    setState(() => tasks.removeAt(index));
  }

  @override
  void dispose() {
    controller.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Mis tareas')),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(children: [
          Row(children: [
            Expanded(child: TextField(
              controller: controller,
              decoration: const InputDecoration(
                labelText: 'Nueva tarea', border: OutlineInputBorder()),
              onSubmitted: (_) => addTask(),
            )),
            const SizedBox(width: 8),
            FilledButton(onPressed: addTask, child: const Icon(Icons.add)),
          ]),
          const SizedBox(height: 16),
          Expanded(child: tasks.isEmpty
            ? const Center(child: Text('Aún no tienes tareas.'))
            : ListView.builder(
                itemCount: tasks.length,
                itemBuilder: (context, index) {
                  final task = tasks[index];
                  return Card(child: ListTile(
                    leading: Checkbox(value: task.done,
                      onChanged: (value) => toggleTask(index, value)),
                    title: Text(task.title,
                      style: TextStyle(decoration: task.done
                        ? TextDecoration.lineThrough : null)),
                    trailing: IconButton(
                      tooltip: 'Eliminar tarea',
                      icon: const Icon(Icons.delete_outline),
                      onPressed: () => deleteTask(index),
                    ),
                  ));
                },
              )),
        ]),
      ),
    );
  }
}
  1. Conecta un emulador o dispositivo con depuración USB habilitada y autorizada.
  2. En la carpeta del proyecto ejecuta flutter run. Para compilar una versión Android de distribución, revisa la guía oficial de despliegue y firma; no compartas claves de firma.
  3. Prueba agregar una tarea, marcarla, desmarcarla, eliminarla y enviar el formulario con el campo vacío.
Alcance: este ejemplo mantiene tareas en memoria. Al cerrar la aplicación se pierden; para conservarlas agrega persistencia local o una base de datos después de estudiar almacenamiento seguro.

CAPÍTULO 08

Ejercicios prácticos

Nivel básico

  1. Declara variables para tu alias, edad y juego favorito; muestra una frase con esos datos.
  2. Calcula el promedio de tres calificaciones y muestra si es aprobatorio según un umbral que tú declares.
  3. Crea una función que convierta minutos en segundos.
Soluciones orientativas del nivel básico
alias = "Player01"
edad = 18
juego = "Aventura"
print(alias, edad, juego)

calificaciones = [8, 9, 7]
promedio = sum(calificaciones) / len(calificaciones)
print(promedio, "Aprobado" if promedio >= 7 else "No aprobado")

def a_segundos(minutos):
    return minutos * 60
print(a_segundos(5))

Nivel intermedio

  1. Modifica la lista Flutter para editar una tarea antes de borrarla.
  2. Añade al portafolio una tarjeta nueva y un filtro por categoría.
  3. En Godot, limita el movimiento del personaje dentro del área visible.
Pistas del nivel intermedio
  • Para editar Flutter, abre un diálogo con un campo de texto y actualiza el elemento dentro de setState.
  • Para filtrar tarjetas, añade un atributo data-categoria y compara el valor seleccionado.
  • Para limitar al personaje, usa clampf(position.x, min_x, max_x) y su equivalente en Y.

Nivel de aplicación

  1. Construye un mini juego con tres niveles y puntuación.
  2. Amplía la lista Flutter para guardar localmente las tareas.
  3. Publica tu portafolio en un hosting estático y valida el diseño móvil.

Entrega: captura o enlace del resultado, descripción del objetivo, herramientas usadas, dificultad encontrada y cómo la resolviste.

Proyecto final

Elige una ruta y construye un producto pequeño pero terminado. La meta es demostrar el proceso completo, no competir por la cantidad de funciones.

Opción A · Videojuego 2D

Objetivo: juego con personaje, objetivo, puntuación y pantalla final. Herramienta: Godot 4. Entrega: proyecto, controles, instrucciones y video corto de prueba.

Opción B · Aplicación móvil

Objetivo: lista de tareas con alta, completado y eliminación. Herramienta: Flutter. Entrega: código, capturas en emulador y explicación de estado y almacenamiento.

Opción C · Página web

Objetivo: portafolio responsivo con navegación y una interacción. Herramientas: HTML, CSS y JavaScript. Entrega: archivos y enlace publicado si tienes hosting.

Procedimiento

  1. Escribe el problema y a quién ayuda tu proyecto.

  5. Construye una función a la vez y realiza pruebas.

CAPÍTULO 01

Introducción al mundo del streaming

El streaming transmite audio y video por internet para que otras personas lo consuman mientras llega la señal. Un streamer es quien realiza la transmisión; el chat permite conversar; la audiencia son las personas que miran y la comunidad reúne a quienes participan de forma recurrente.

Formatos posibles

  • Gameplay y comentarios de videojuegos.
  • Tutoriales, clases y demostraciones.
  • Música, arte o procesos creativos, respetando derechos.
  • Charlas, entrevistas y eventos.
  • Contenido IRL o desde dispositivos móviles, con especial cuidado de la privacidad.

Una transmisión puede ser pública, privada o no listada según la plataforma y el tipo de evento. Antes de salir en vivo define el propósito, la audiencia, los límites personales y qué información nunca debe aparecer en pantalla.

CAPÍTULO 03

Equipo necesario

No necesitas comprar todo antes de empezar. Prioriza conexión estable, audio entendible y un equipo que pueda codificar sin sobrecalentarse.

NivelConfiguración orientativaUso
EconómicoComputadora o celular existente, audífonos con micrófono, luz ambiental frontal y soporte estable.Pruebas, charla o directos sencillos.
IntermedioPC con CPU/GPU compatible, micrófono USB, audífonos cerrados, cámara web y luz LED difusa.Gameplay con escenas, cámara y fuentes.
AvanzadoEquipo dedicado o doble PC, micrófono XLR con interfaz, cámara, iluminación controlada, capturadora y red cableada.Producción compleja con varias fuentes.

Qué hace cada componente

  • CPU/GPU: ejecutan juego y codificación; la carga depende del juego, resolución y encoder.
  • Micrófono: capta voz; colócalo cerca y fuera del flujo directo de aire.
  • Audífonos: evitan que el audio de altavoces vuelva al micrófono.
  • Cámara: opcional; mejora presencia, pero exige iluminación.
  • Iluminación: una luz suave frente al rostro suele mejorar más que una cámara costosa con poca luz.
  • Capturadora: lleva video de consola/cámara al PC; comprueba compatibilidad y resolución.

Antes de comprar, confirma conexiones, compatibilidad del sistema, uso previsto y presupuesto. Prueba el equipo que ya tienes.

CAPÍTULO 04

Conexión a internet

La velocidad de subida es la capacidad para enviar el video; la descarga es la capacidad para recibir datos. El ping mide el tiempo de ida y vuelta; la latencia es el retraso percibido; la pérdida de paquetes significa que parte de los datos no llega. Para transmitir importa especialmente la subida estable, no solo el valor máximo anunciado.

Cómo probar

  1. Conecta la computadora por Ethernet cuando sea posible.
  2. Detén descargas, copias en nube y otros streams de la red.
  3. Ejecuta dos o tres pruebas en diferentes horarios con una herramienta de medición reconocida.
  4. Registra subida, ping y variación entre pruebas.
  5. Inicia una grabación o directo privado de prueba y observa pérdida de cuadros y salud de la transmisión.

Como regla práctica, reserva margen sobre el bitrate que configuraste: no uses toda la subida disponible. Si hay otras personas compartiendo conexión, reduce resolución o bitrate.

CAPÍTULO 06

Aprende a utilizar OBS Studio

OBS Studio es software gratuito y de código abierto para grabar y transmitir. Descárgalo únicamente desde obsproject.com. La ubicación exacta de algunos menús puede variar entre versiones.

Configuración paso a paso

  1. Descarga e instalación: selecciona el instalador de tu sistema operativo desde el sitio oficial, ejecútalo y abre OBS.
  2. Asistente inicial: permite que el asistente de configuración automática evalúe transmisión o grabación; úsalo como punto de partida, no como garantía.
  3. Interfaz: identifica Escenas, Fuentes, Mezclador de audio, Transiciones y Controles.
  4. Escena: crea una llamada Juego. Las escenas son composiciones distintas.
  5. Fuentes: agrega Captura de juego o Captura de ventana; agrega Dispositivo de captura de video solo si usarás cámara. Coloca y redimensiona cada fuente en la vista previa.
  6. Micrófono: en Ajustes > Audio selecciona el dispositivo correcto. Habla y observa que el medidor responda sin llegar constantemente al rojo.
  7. Audio de escritorio: selecciona la salida que deseas capturar o agrega captura de audio por aplicación cuando esté disponible. Usa audífonos para reducir eco.
  8. Video: en Ajustes > Video define resolución base del lienzo y resolución de salida. Empieza con 1280×720 o 1920×1080 según equipo/red y 30 FPS; aumenta solo si la prueba es estable.
  9. Bitrate y codificador: en Ajustes > Salida > Emisión usa CBR cuando la plataforma lo recomiende. Elige encoder de hardware compatible si ofrece buena estabilidad; de lo contrario prueba software. No copies valores de otra plataforma sin verificar.
  10. Conexión: desde Ajustes > Emisión elige plataforma/servidor e inicia sesión mediante el flujo oficial o configura servidor y clave de emisión.
  11. Clave: trátala como contraseña. No la pongas en capturas, chat, repositorios ni archivos públicos. Si se filtra, revócala y genera otra desde la plataforma.
  12. Prueba: realiza una grabación local y una emisión privada/no listada si la plataforma lo permite. Reproduce el archivo y comprueba audio, imagen, sincronía y legibilidad.

Filtros de audio

  • Supresión de ruido: reduce sonidos constantes de fondo; demasiada intensidad puede deformar la voz.
  • Compresor: reduce diferencias entre voz baja y picos altos; no sustituye hablar a distancia constante.
  • Limitador: fija un techo para evitar picos excesivos. Ajusta con una prueba real y evita saturación.
Orden de trabajo: primero coloca el micrófono y ajusta su nivel; después aplica filtros suaves uno por uno y escucha una grabación. No agregues filtros por rutina si no resuelven un problema.

Guía y manual oficial: OBS Knowledge Base.

CAPÍTULO 07

Creación de una transmisión atractiva

Organiza escenas para que el espectador entienda qué está ocurriendo. No necesitas muchos efectos: prioriza lectura, equilibrio visual y transiciones breves.

INICIO
Horario y reglas
→
EN VIVO

→
DESCANSO
Pausa y aviso
→
DESPEDIDA
Gracias y cierre
  • Pantalla de inicio: informa que comenzarás pronto; no dejes datos sensibles.
  • Escena principal: deja el juego como foco; cámara y chat no deben tapar información importante.
  • Descanso: silencia fuentes que no deban sonar y muestra un aviso.
  • Despedida: comunica que terminó y apaga la transmisión desde la plataforma/OBS.
  • Alertas y overlays: usa recursos ligeros, de fuentes confiables y con derechos claros.

Para videojuegos puedes iniciar con tres escenas: Inicio, Juego y Enseguida volvemos. Duplica la escena solo cuando necesites una composición realmente diferente.

CAPÍTULO 08

Streaming desde consola y celular

Las opciones dependen del modelo, versión del sistema, aplicación, región y elegibilidad de tu cuenta. Antes de seguir un tutorial, confirma que corresponda a tu consola o dispositivo exacto.

PlayStation y Xbox

  1. Actualiza el sistema y conecta la cuenta de la plataforma desde los ajustes oficiales.
  2. Revisa qué servicios de transmisión están disponibles en tu región y cuenta.
  3. Configura título, micrófono, cámara opcional y privacidad antes de comenzar.
  4. Haz una prueba de audio y evita mostrar mensajes, nombres reales o notificaciones privadas.
  5. Para overlays, escenas avanzadas o capturas de otras fuentes, quizá necesites una capturadora y computadora; verifica la compatibilidad HDMI/HDCP y el software antes de comprar.

Celular

  1. Instala la aplicación oficial desde la tienda autorizada.
  2. Revisa permisos de cámara, micrófono y notificaciones; concede solo los necesarios.
  3. Usa soporte estable, orientación adecuada e iluminación frontal.
  4. Activa modo No molestar y oculta notificaciones personales.
  5. Comprueba batería, temperatura, datos móviles y Wi-Fi antes del directo.

No se promete que toda cuenta pueda transmitir desde cualquier dispositivo: algunas plataformas aplican requisitos de acceso y restricciones locales. Usa las páginas oficiales de soporte antes de planear una emisión.

CAPÍTULO 09

Interacción con los espectadores

La interacción construye un espacio amable y seguro. Da la bienvenida sin exigir que alguien revele información personal; responde preguntas con calma y reconoce que puedes no saber una respuesta.

Frases de ejemplo

  • Bienvenida: “¡Hola! Gracias por pasar. Hoy vamos a jugar y conversar un rato”.
  • Pregunta: “¿Qué estrategia probarían en esta parte?”.
  • Pausa: “Voy a tomar un minuto; regreso enseguida”.
  • Límite: “No compartamos datos personales ni enlaces sospechosos en el chat”.
  • Despedida: “Gracias por acompañarme. Nos vemos en la próxima transmisión”.

Moderación

  • Escribe reglas claras y visibles.
  • Define qué comportamientos ameritan advertencia, silencio o bloqueo.
  • Asigna moderadores de confianza y explica sus permisos.
  • No respondas a provocaciones que busquen exponer datos o acosar.
  • Reporta conductas graves usando las herramientas oficiales.

CAPÍTULO 10

Cómo crecer como streamer

El crecimiento no está garantizado y no depende de una sola configuración. La constancia sostenible, una propuesta reconocible y la calidad de interacción pueden ayudarte a aprender qué contenido funciona.

  1. Identidad: define temática, tono y una descripción honesta del canal.
  2. Audiencia: piensa a quién va dirigido y qué valor recibirá.
  3. Calendario: elige horarios que puedas mantener sin afectar descanso, estudio o trabajo.
  4. Títulos y miniaturas: explica el contenido sin engañar ni prometer algo que no aparece.
  5. Clips: selecciona momentos útiles o entretenidos y revisa derechos de música, imágenes y participantes.
  6. Redes: reutiliza fragmentos adaptados a cada formato y respeta normas de cada servicio.
  7. Estadísticas: observa retención, interacción y fuentes de tráfico como señales, no como valoración personal.

Evita comprar seguidores, bots, interacciones falsas o pagar por promesas de crecimiento garantizado. Prueba un cambio cada vez y registra resultados durante un periodo razonable.

CAPÍTULO 11

Seguridad, privacidad y derechos de autor

  • Cuenta: contraseña única, autenticación multifactor y correo de recuperación protegido.
  • Datos: oculta notificaciones, direcciones, documentos, matrículas, geolocalización y nombres de terceros sin consentimiento.
  • Enlaces: no abras archivos o enlaces de usuarios desconocidos ni entregues códigos de acceso.
  • Moderación: configura filtros, bloqueos y reglas; conserva pruebas de incidentes graves sin exponerlas públicamente.
  • Música: usa música propia, licenciada para streaming o con permiso claro para el uso previsto. “Libre de regalías” no significa automáticamente libre de restricciones.
  • Video y juegos: revisa políticas de contenido del titular, avisos de spoilers y restricciones de retransmisión.
  • Personas: pide consentimiento antes de mostrar o grabar a terceros, especialmente menores.
Clave de emisión: nunca publiques la clave, token de plataforma, QR de inicio de sesión ni capturas del panel que los revelen. Si sospechas que se filtró, restablécela inmediatamente.

Consulta los términos de la plataforma y las licencias originales de cada recurso. Este manual es educativo y no sustituye asesoría legal.

CAPÍTULO 13

Tu primera transmisión en vivo

Antes de salir

  • Cuenta segura y permisos de transmisión confirmados.
  • Título, categoría y privacidad revisados.
  • Micrófono y audífonos probados.
  • Escenas de inicio, directo y descanso preparadas.
  • Internet probado; preferencia por cable Ethernet.
  • Notificaciones privadas desactivadas.
  • Fuentes visuales y música autorizadas.
  • Moderador o reglas de chat definidos, si aplica.
  • Grabación local de prueba revisada.

Durante el directo

  1. Inicia la escena de espera y confirma la señal.
  2. Inicia emisión desde OBS o desde el dispositivo según tu flujo.
  3. Revisa la vista previa/salud de transmisión de la plataforma.
  4. Saluda, explica el contenido y mantén el ritmo.
  5. Observa el chat sin mostrar mensajes privados ni abrir enlaces sospechosos.
  6. Si hay un problema técnico, pausa o muestra una escena de descanso y corrige.

Al terminar

  1. Agradece y comunica el cierre.
  2. Detén la transmisión en el orden recomendado por la plataforma.
  3. Confirma que terminó; detén la grabación local si está activa.
  4. Revisa el archivo antes de publicarlo y elimina datos sensibles.
  5. Anota una mejora concreta para la siguiente sesión.

CAPÍTULO 14

Proyecto final: crea tu propio canal

Diseña un canal de prueba y realiza una emisión privada/no listada cuando el servicio lo permita, o una grabación local si aún no tienes permiso para emitir.

Entregables

  1. Nombre, tema, descripción y público al que va dirigido.
  2. Plataforma seleccionada y motivo.
  3. Imagen de perfil/portada creada con recursos propios o autorizados.
  4. Escenas: inicio, principal, descanso y despedida.
  5. Prueba de micrófono, audio de escritorio, video y conexión.
  6. Grabación o enlace de prueba que no exponga información privada.
  7. Reflexión: qué funcionó, qué falló y qué cambiarás.

CAPÍTULO 15

Glosario de streaming

Bitrate
Cantidad de datos transmitidos por segundo; influye en calidad y ancho de banda.
Chat
Canal de mensajes de quienes miran el directo.
Codificador
Software o hardware que comprime audio y video para transmitir.
Capturadora
Dispositivo que recibe una señal de video externa para grabarla o transmitirla.
Escena
Composición de fuentes en OBS.
Fuente
Elemento de una escena: juego, ventana, cámara, imagen o audio.
FPS
Cuadros por segundo; indica cuántas imágenes se muestran en un segundo.
Latencia
Retraso entre la acción y lo que recibe el espectador.
Moderador
Persona con permisos para ayudar a mantener las reglas del chat.
OBS
Open Broadcaster Software, aplicación de grabación y streaming.
Overlay
Gráfico superpuesto al contenido, como marco, alertas o panel.
Ping
Tiempo de ida y vuelta de un paquete de red.
Resolución
Dimensiones de imagen, por ejemplo 1280 × 720.
RTMP/RTMPS
Protocolos de ingestión de video; RTMPS cifra la conexión.
VOD
Video bajo demanda, grabación disponible después del directo si la plataforma la conserva.
CBR
Modo de codificación con bitrate constante.
